= FPSOT signed records and transparency log specification

Rules for how a public body seals the records that it issues, publishes proof of them and keeps them verifiable for decades.
The word "log" here means a public transparency log of sealed records, not the logs of software, which the FPSOT observability specification covers.
Each record gets an ETSI advanced electronic seal with a trusted time stamp.
A salted hash of it goes into a C2SP transparency log that independent witnesses cosign, and the reader gets an offline proof.
Records kept for decades also get RFC 4998 evidence records, which outlive the seal algorithms.
The rules name capabilities and standards, not products. Version 0.1 is a draft.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Each requirement has an ID from `LOG-001` to `LOG-093`.

* Choose the profile of each series of records: `seal`, `seal-log` or `seal-log-preserve` (LOG-002).
  The table "Profiles" in `spec/en/index.adoc` lists the rules of each.
* Seal in the format that fits the media type, at level B-LT, with ECDSA P-384 or RSA of 3072 bits or more (LOG-010 to LOG-016).
* Publish your trust-anchor sets, and keep a seal manifest with each record (LOG-017 to LOG-019).
* Log a salted hash of the exact sealed bytes, and follow the integrity rules of the observability specification (LOG-030 to LOG-038).
* Publish a witness policy with public and domestic witnesses, and deliver a proof with each record (LOG-040 to LOG-057).
* Run `bash examples/test-examples.sh` to check the example files. The script `examples/check-examples.py` checks a folder with the same four files.

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
It takes a series of outbound records to the `seal-log` profile.
A request for proposals can require a sealing service, a log or a verifier to meet a profile or a role of this specification (LOG-001, LOG-002).
The comparison data in `jurisdictions/` shows how the guidance of Canada and Québec differs.
The pages `reference-stack.adoc` and `questions-for-counsel.adoc` are informative, and the latter lists the legal questions that a lawyer must settle.
This specification is not legal advice.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book, published as PDF with each release.

| `docs/`
| Guides, in the Antora folder layout.

| `examples/`
| A witness policy, a proof, a seal manifest, a stand-in for the sealed bytes, and the scripts that check them.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules.

| `diagrams/`
| PlantUML sources and their rendered SVG files.

| `jurisdictions/`
| Comparison data: how each government handles the same topics.
